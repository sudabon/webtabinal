## Context

動機は proposal.md の Why を参照。設計上の前提は次のとおり。

- `session.Manager` はセッションをメモリだけで保持し、永続化は一切していない。`Info` には `Order` / `Cwd` / `Memo` と、`agentdetect` 由来の `Agent` / `AgentState` が入る。
- `Info.Cwd` は OSC 7 で追従する実 cwd。`applyEvent` は `EventCWD` / `EventPrompt` を受けた時点で `starting` を抜けて `idle` になるため、「シェルが入力を受け付けられる状態」は既存の状態機械から読める。
- `Manager` のフックは各 1 本しか持てない（`SetHooks` は上書き）。既に `server.Hub` が全フックを握っているため、新機能がフックを奪うことはできない。
- `Manager` には 1 秒周期の `fallbackLoop` が既にあり、周期処理は既存の設計と整合する。
- `runServe` は `signal.NotifyContext` でグレースフル終了し `mgr.Close()` を呼ぶが、SIGKILL・電源断ではこの経路を通らない。
- ネイティブ `.app` はデーモンを別セッションで起動するため、アプリ終了だけではデーモンは落ちない。復元が必要になるのは再起動・ログアウト・`launchctl` 再読み込み・クラッシュ・手動停止の場合。
- `agent-state-detection` の spec は「Detection is observation-only」を要求しており、マニフェストは観測の定義しか持てない。

## Goals / Non-Goals

**Goals:**

- デーモンが落ちても、エージェントを動かしていたタブの cwd・メモ・順序・エージェント種別が最大 5 秒の遅れで残る。
- 次回起動時に、UI が接続する前にタブが揃い、シェルのプロンプト到達後に resume コマンドが自動実行される。
- 自動実行の対象を、設定表から解決した既知エージェントのコマンドだけに限定する。

**Non-Goals:**

- エージェントの会話 ID を特定した厳密な再開（hook 連携が必要。今回は cwd ベースの「直近の会話」再開に留める）。
- 端末のスクロールバック内容やエージェントの出力の復元。
- エージェントを動かしていない素のシェルタブの復元。
- 復元済みタブを示す API フィールドや UI バッジの追加。

## Decisions

### 1. スナップショットは専用ファイルに置き、原子的に置換する

`~/Library/Application Support/WebTabinal/restore.json`（`internal/paths` に `RestorePath()` を追加）に schema v1 の JSON を保存する。書き込みは同一ディレクトリの一時ファイル → `os.Rename` で置換し、パーミッションは 0600。

- 代替: `config.json` に相乗り。→ 却下。config はユーザーが手で編集するファイルで、数秒ごとに書き換わる運用データを混ぜると編集と競合する。
- 代替: SQLite などのストア。→ 却下。数十エントリの配列に対して過剰。

### 2. 記録は 5 秒周期の差分書き込み + 終了時の同期書き込み

`internal/restore` の Recorder が 5 秒ごとに `Manager.List()` からエントリを組み立て、直前に書いた内容と異なるときだけ書き込む。加えてデーモン終了時（`mgr.Close()` の前）に同期的に 1 回書く。

- 代替: `Manager` の変更フックに相乗り。→ 却下。フックは Hub が使用済みで、しかも cwd 追従（OSC 7）はセッション一覧の変更通知を必ずしも伴わない。周期比較なら cwd の変化も自然に拾える。
- 代替: 終了時だけ書く。→ 却下。クラッシュ・電源断という主要ケースで何も残らない。
- トレードオフ: 直前 5 秒の変更は失われる。cwd とエージェント種別しか記録しないため実害は小さい。

### 3. 復元の組み立ては `cmd/webtabinal` の `runServe` が行う

`internal/restore` は「スナップショットの読み書き」と「resume コマンドの解決・検証」だけを持ち、`session` パッケージには依存しない。`runServe` が Manager 作成後・HTTP の待ち受け開始前に復元パスを実行し、その後 Recorder を起動する。

- 理由: `session` が `restore` に依存すると、逆向きに Manager の情報も必要になり循環しやすい。復元のポリシー（順序・上限・スキップ）は純粋関数としてテストしたい。
- `Manager` に足す口は最小限にする: 復元用のセッション作成（cwd とメモを与える）と、「プロンプト到達後に指定文字列を 1 回だけ書く」予約。

### 4. コマンド投入はシェル準備待ちのポーリングで行う

セッション作成後、25 ms 間隔で `Info().State` を見て `starting` を抜けたら投入する。抜けないまま 2000 ms 経過したら投入する（統合スクリプトが入っていないシェル向けのフォールバック）。投入は 1 セッションにつき 1 回だけ。

- 代替: OSC イベントフックを購読。→ 却下。フックは Hub が保持しており、複数購読の仕組みを新設するコストが見合わない。
- 代替: 固定待ち時間だけ。→ 却下。zsh の初期化が遅い環境で先頭文字が欠ける。

### 5. resume コマンド表は config に持ち、検知マニフェストには持たせない

組み込み表は Go 側の定数（`claude` → `claude --continue`、`codex` → `codex resume --last`、`cursor-agent` → `cursor-agent resume`）とし、`config.json` の `restore.commands`（`map[string]string`）が同じキーで上書きする。空文字はそのエージェントの復元を無効化する。

- 理由: `agentdetect` のマニフェストは spec 上「観測専用」。実行するコマンドを持たせると、ローカルマニフェストを置くだけで起動時に任意コマンドが走る経路ができてしまう。
- 検証: 解決後のコマンドは trim 後非空・CR/LF を含まない・512 文字以内。config patch 時にも同じ検証を掛け、壊れた値が保存されないようにする。

### 6. 同一 `(agent, cwd)` の 2 本目以降は「入力するだけ」

`claude --continue` も `codex resume --last` も cwd 基準で直近の会話を選ぶため、同じディレクトリの 2 タブを両方自動実行すると同一会話を二重に開く。先頭 1 本だけ改行付きで実行し、残りは改行なしで入力行に置く。

- 代替: 2 本目以降をタブごと復元しない。→ 却下。タブ自体（cwd とメモ）は復元したい。
- 将来: hook 経由で会話 ID を記録できれば、この分岐は不要になる。

### 7. 復元済みであることは API に持たせない

端末のスクロールバックに実行されたコマンドがそのまま残るため、それが利用者への表示になる。スキップ・拒否はデーモンログに理由付きで残す。

## Risks / Trade-offs

- 起動時に自動でコマンドが走る（意図しないエージェント起動・API 消費） → 既定表と config のコマンドだけを実行し、`restore.enabled` のトグル、`max_sessions`（既定 8）、`max_age_hours`（既定 72）、cwd 存在確認、コマンド検証で範囲を絞る。
- `claude --continue` が意図と違う会話を拾う（同一 cwd で複数会話） → `(agent, cwd)` 重複は 1 本だけ自動実行し、残りは入力のみ。厳密な会話 ID は将来の hook 連携で解決する。
- `cursor-agent resume` が対話ピッカーを開き、自動実行に向かない可能性 → 既定は組み込み表のままにし、合わない場合は `restore.commands` の空文字で無効化、または別コマンドに差し替え可能にする。
- クラッシュ直前 5 秒の記録欠落 → 記録項目が cwd とエージェント種別だけなので影響は限定的。周期短縮より書き込み回数の抑制を優先する。
- 復元直後にユーザーが入力し、投入コマンドと混ざる → 投入はプロンプト到達直後の 1 回のみ。タブは復元順に作られ、投入は各セッション独立に行う。
- `restore.json` にプロジェクトパスが残る → 0600 で保存し、README で「共有しない」ことを config.json と同様に明記する。
- 復元ループ（毎回同じエントリを復元し続ける） → 復元後は Recorder が生きているセッションでファイルを上書きするため、resume に失敗して落ちたタブは次回のスナップショットから消える。

## Migration Plan

- 新規ファイルの追加だけで、既存の永続データの形式は変えない。旧 config は `applyDefaults` で `restore` の既定値が埋まる。
- ロールバック: 設定 UI か config の `restore.enabled=false`。既に作られた `restore.json` は削除して構わない（存在しなければ復元は行わない）。
- 段階確認: `restore.enabled=false` でスナップショットだけ先に確認 → 有効化して復元を確認、という順で検証できる。

## Open Questions

- `cursor-agent resume` の実機挙動（ピッカーか直近再開か）を確認し、組み込み既定値を最終決定する。表の値だけの変更で、spec とタスク分割には影響しない。
- `claude` の既定を `--continue` のままにするか、将来 hook で会話 ID を記録して `--resume <id>` に寄せるか。今回は `--continue` で確定し、ID 記録は別変更として扱う。
