## Why

`close_tab_on_clean_exit` は既定で有効なのに、シェルを `exit` / Ctrl+D で終わらせてもタブが残ることがある。原因は「クリーンな終了」を **シェルプロセスの終了コードが 0 であること** だけで判定している点にある。bash も zsh も、引数なしの `exit`（および Ctrl+D）は **直前のコマンドの終了ステータス** をそのまま返すため、`grep` が何もマッチしなかった、テストが落ちた、Ctrl+C でコマンドを中断した（130）といった直後に終了すると、ユーザーが明示的に閉じたにもかかわらず終了コードが非 0 になりタブが残る。実機での再現でも `false` → `exit` は bash / zsh とも exit=1 になり、タブが残ることを確認した。ユーザーからは「閉じるときと閉じないときがある」＝バグとして見えている。

## What Changes

- シェル統合（zsh / bash）が、シェルが自分で終了する直前に「シェル終了」シグナルを OSC で 1 回だけ発行する。zsh は `zshexit` フック、bash は `EXIT` トラップを使い、いずれも既存のユーザー定義フック／トラップを壊さないよう連鎖させる。
- OSC パーサに「シェル終了」イベント種別を追加し、セッションはそのイベントを受け取ったことを記録する。このイベントは端末ストリームへの転送を妨げず、CWD・コマンド・idle/running 状態を変更しない。
- タブ自動クローズの判定を「終了コードが 0」から「**シェルが自分の意思で終了した**」に変える。具体的には `close_tab_on_clean_exit` が true のとき、シェル終了シグナルを受け取っていれば終了コードに関わらずタブを閉じ、受け取っていなくても終了コードが 0 なら従来どおり閉じる。
- 起動に失敗したシェル（初回プロンプトに到達せず `Integrated=false` のまま終了）は、終了コードに関わらずタブを残す。シェル設定ミスのエラー出力が一瞬で消えないようにするためのセーフガード。
- PTY の終了処理で、読み出しループが最後の出力を処理し終えるのを（上限付きで）待ってから終了ハンドラを呼ぶ。終了直前に出た OSC シグナルが取りこぼされないようにする。
- **BREAKING**（挙動）: `close_tab_on_clean_exit` の意味が「終了コード 0 のときに閉じる」から「シェルが自分の意思で終了したときに閉じる」に広がる。設定キー名・既定値（`true`）・型は変わらないため、config の移行は不要。統合が効いていないシェルでは従来どおり終了コード 0 のみで閉じる。

## Capabilities

### New Capabilities
（なし）

### Modified Capabilities
- `shell-integration`: zsh / bash 統合スクリプトがシェル終了時に OSC のシェル終了シグナルを発行すること、およびパーサがそれを解釈することを追加
- `session-pty`: タブ自動クローズの判定条件を「終了コード 0」からシェル終了シグナル基準に変更し、プロンプト到達前に終了したセッションはタブを残すことを追加

## Impact

- Go: `internal/osc/parser.go`（OSC 9973 の終了サブタイプと新イベント種別）、`internal/session/session.go`（シェル終了フラグの記録、readLoop 完了待ち）、`internal/session/manager.go`（`handleExit` の判定条件）
- シェル統合スクリプト: `internal/integration/integration.zsh`、`internal/integration/integration.bash`（バージョン更新に伴い Application Support 配下のファイルが上書きされる）
- 設定: 変更なし（`close_tab_on_clean_exit` のキー・型・既定値はそのまま、意味だけが広がる）
- フロントエンド: 変更なし。タブ削除は既存の `sessions` ブロードキャストで反映される
- ドキュメント: README の `close_tab_on_clean_exit` の説明を新しい意味に更新
- 副作用: 既定有効のため、これまで残っていた「非 0 終了だがユーザーが閉じたタブ」が閉じるようになる。スクロールバックを見返したいユーザーには挙動変化として見える
