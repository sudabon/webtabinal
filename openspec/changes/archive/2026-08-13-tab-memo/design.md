## Context

サイドバーの各タブは `session.Session` に対応し、REST / WS の `SessionInfo` で CWD・コマンド・状態を表示している。タブ操作はクリック切替、DnD 並び替え、コンテキストメニュー（duplicate / restart / close）まで。設定モーダルはあるが、タブ固有の短い注釈を付ける手段はない。

メモは「このタブは何用か」のラベルであり、PTY 出力や config.json とは別のセッションメタデータとして扱う。

## Goals / Non-Goals

**Goals:**

- タブのダブルクリックでメモ編集モーダルを開く
- 最大 30 文字（Unicode コードポイント）を保存・クリアできる
- メモがあるタブを約 2 秒ホバーするとツールチップを出す
- メモをデーモン上のセッションに保持し、再接続後も同じセッションで見える
- restart（同一タブの再生成）ではメモを引き継ぐ

**Non-Goals:**

- デーモン再起動後まで残る永続化（セッション自体が消えるため）
- タブタイトルの置き換えや CWD 行への常時表示
- リッチテキスト、複数行メモ、タグ、検索
- ネイティブ `title` による即時ツールチップ（遅延制御できないため使わない）
- 設定画面へのメモ一覧

## Decisions

### 1. 保存先はデーモンの `Session.Memo`

- **選択**: `session.Session` に `Memo string` を持ち、`Info` JSON の `memo` として返す
- **理由**: ウィンドウを閉じてもデーモンとセッションは残る。localStorage だと再接続・複数クライアントで分裂する
- **代替案**: `localStorage`（セッション ID キー）→ 再接続は同じ ID なら動くが、restart で ID が変わる現状と合わない。config.json → セッション寿命と無関係な設定ファイルを汚す

### 2. 更新 API は `PATCH /api/sessions/{id}`

- **選択**: `{ "memo": "<string>" }` を受け、バリデーション後に保存し、更新済み `SessionInfo` を返す。既存の WS `sessions` ブロードキャストで他クライアントも同期
- **理由**: セッション単位の部分更新として自然。新規 verb を増やさない
- **代替案**: `PUT /api/sessions/{id}/memo` → 専用で分かりやすいが、1 フィールドのためにエンドポイントを増やす必要はない

### 3. 文字数は Unicode コードポイント 30

- **選択**: Go `utf8.RuneCountInString`、フロントは `Array.from(value).length`。超過は API が 400、フォームは入力時点で打ち止め
- **理由**: 日本語 30 文字の直感に合う。バイト数だと漢字で約 10 文字相当になり短い
- **代替案**: grapheme cluster（絵文字 ZWJ）→ 実装コストに対して本機能の価値が低い。先頭末尾の空白は trim してからカウント・保存する

### 4. ライフサイクル

- **create**: `memo` は空
- **duplicate**: コピーしない（別セッション）
- **restart**: 現行実装は新しい UUID のセッションを作って旧セッションを消すため、**新セッションへ memo をコピーする**
- **delete / デーモン再起動**: 消える

### 5. 編集 UI

- 小さなダイアログ（設定モーダルのシェルは使わない）。`role="dialog"`、Esc / 背景 / キャンセルで閉じる
- 単一行 input、`maxlength` 相当の 30 コードポイント制限、残り文字数表示
- 保存で PATCH。空（trim 後）はメモ削除。失敗時は既存 toast でエラー、モーダルは開いたまま
- ダブルクリックはタブ全体。1 回目の click で選択、2 回目でモーダル。DnD の `distance: 6` は維持し、ドラッグ開始とは両立させる

### 6. ツールチップ

- カスタムツールチップ。ホバー開始から **2000ms** 後に表示。ポインタがタブを離れるかモーダルが開いたら消す
- `memo` が空ならタイマーも表示もしない
- コマンド行の native `title`（省略コマンド全文）は残す。メモツールチップはタブの外側（またはタブに隣接）に出し、native title と同時に重ならない位置にする

## Risks / Trade-offs

- [restart で ID が変わりメモが落ちる] → Restart 時に memo を新セッションへコピーする
- [ダブルクリックと DnD / クリック選択の競合] → PointerSensor の距離制約を維持。dblclick ハンドラは `preventDefault` しないが、2 回目の click での選択は許容
- [コマンド行 `title` とメモツールチップが重なる] → メモは遅延カスタム、位置をタブの右または下に固定
- [複数クライアントで同時編集] → last-write-wins。想定利用者はローカル 1 ユーザー

## Migration Plan

1. `Session` / `Info` に `memo` を追加（ゼロ値は `""`）。既存クライアントは未知フィールドを無視できる
2. `PATCH /api/sessions/{id}` とフロント UI を同時に入れる
3. ロールバック: エンドポイントを外せば旧 UI のまま。メモリ上の memo はプロセス寿命なので移行データなし
