## Context

`internal/config.Config.Shell` は絶対パスで、デフォルトは `/bin/zsh`。`PATCH /api/config` は相対パス・未存在・非実行可能を既に拒否する。`session.Manager.Create` は生成時に `cfg.Shell` を読み、`zsh -il` 相当（設定シェルに `-il`）で PTY を起動する。zsh のときだけ OSC 統合を注入する。

設定モーダルは左ナビ + 右ペインで、現状カテゴリは「外観」のみ。変更は即時 PATCH、保存ボタンなし。テーマはラジオのクリックで即保存しているが、パス入力は途中文字列が無効になりうる。

## Goals / Non-Goals

**Goals:**

- 設定から起動シェルの絶対パスを編集できる
- 無効値は保存せず、エラー表示して直前の有効値に戻す
- 新規タブ・複製・終了後 restart は新しい `shell` を使う
- 開いているセッションのシェルは変えない

**Non-Goals:**

- bash / fish 向けの OSC シェル統合
- ファイルピッカーやシェル検出（`/etc/shells` の列挙）
- 開いているタブの自動再起動
- デフォルト値の変更（新規 config は引き続き `/bin/zsh`）
- フォント・通知など他の既存設定のモーダル移行

## Decisions

### 1. UI は任意パスのテキスト入力

- **選択**: 「一般」カテゴリに単一行の絶対パス入力。プレースホルダ例は `/bin/zsh` と `/bin/bash`
- **理由**: Homebrew bash（`/opt/homebrew/bin/bash`）など、固定プリセットでは足りない
- **代替案**: zsh / bash のラジオのみ → 任意パス要求と合わない。プリセット + カスタムの二段 UI は今回不要

### 2. 確定は blur / Enter。キー入力ごとには PATCH しない

- **選択**: フォーカスアウトまたは Enter で `patchConfig({ shell })`。値が直前の確定値と同じなら送らない
- **理由**: 入力途中の相対パスや未完成パスが毎回 400 になるのを避ける。テーマの即時保存方針は「確定した変更をすぐ書く」として維持する
- **失敗時**: 既存 toast（`reportActionError`）でエラーを出し、入力を last-committed に戻す。テーマ変更と同じパターン

### 3. カテゴリは「一般」を追加し、初期選択は「外観」

- **選択**: 左ナビは「外観」「一般」。開いたときは外観を選択
- **理由**: 既存の外観 UX を変えない。シェルは見た目ではないので外観ペインには置かない
- **代替案**: 初期選択を一般にする → テーマ利用者の導線が変わるので不採用

### 4. 適用タイミングはセッション生成時

- **選択**: 生きている PTY は付け替えない。Create / Duplicate / Restart（いずれも `Manager.Create`）が現在の `cfg.Shell` を使う
- **理由**: 実行中プロセスを殺さず、既存の spawn 経路に乗る
- **UI 注記**: 「新しいタブから適用」程度の短い hint を入力欄の近くに出す

### 5. バリデーションはサーバ既存ルールを正とする

- **選択**: クライアントは空文字の即 PATCH を避ける程度に留め、可否はサーバに任せる
- **既存ルール**: 絶対パス、`os.Stat` 成功、実行ビットあり
- **フロントの追加チェック**: 未実装でよい。失敗時ロールバックがあれば足りる

## Risks / Trade-offs

- [zsh 以外は cwd / コマンドの OSC 統合が無い] → 既存フォールバック（◌ インジケータ + プロセス名ポーリング）。本 change では許容し、hint で触れてもよい
- [macOS の `/bin/bash` は 3.2] → 任意パスなので Homebrew bash を自分で指定できる
- [存在しないパスを入力すると toast が出る] → 意図どおり。入力中は送らないのでノイズは確定時だけ
- [restart は exited のみで、新しい shell になる] → Create 経由のため仕様どおり。生きているタブを新シェルにするには一度閉じて作り直す

## Migration Plan

1. UI から既存 `shell` を読み書きするだけ。config スキーマ変更なし
2. 既存ユーザーの `shell` は `/bin/zsh` のまま。設定で書き換えるまで動作は変わらない
3. ロールバック: 一般カテゴリを外せば旧 UI。保存済みパスはそのまま有効
